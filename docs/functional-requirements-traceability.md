## Verification rules
1. A proposed test ID is not a test case: add setup, input, expected outcomes, forbidden side effects, negative cases and test location before calling it covered.
2. No test is marked passing without a linked run and source revision; separate unit, integration, isolated simulation, real HA verification and deployment evidence.
3. Each requirement must eventually cross-reference its applicable `FR-OPT` governance and domain contracts; the optimisation modules are currently in the committed appendices.
4. Resolve semantic inbound references using [the ID migration register](functional-requirement-id-migration.md). Historical occurrence register describes the pre-fix state.
5. Maintain owner-approved behaviour separately from implementation status. No approval to merge or deploy is implied.
