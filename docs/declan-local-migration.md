# Historical migration: jarvis_local to declan_local

> **Do not repeat on an existing Declan installation.** This procedure applies only to an installation whose config-entry domain is still `jarvis_local`. The owner reports that live Home Assistant Jarvis entity references have already been renamed to Declan. Historical names below are migration input examples, not recommended current entity IDs. See [legacy reference audit](legacy-jarvis-reference-audit.md) before planning further identifier or storage migrations.

New installations can install the integration and add Home Voice Assistant normally. Existing installations require an offline migration. Home Assistant dispatches config-entry migration through the entry's registered domain, so the new package cannot migrate an entry that still belongs to the old domain.

1. Take a full Home Assistant backup and keep the old integration package or release available. Stage the new `custom_components/declan_local` folder outside the config directory. For HACS installations, plan this as a maintenance upgrade and check that the final installed files match step 4.
2. Stop Home Assistant Core. In the config directory, open `.storage/core.config_entries` as JSON. In `data.entries`, locate the entry whose `domain` is exactly `jarvis_local`. Record its `entry_id`. If there is already a `declan_local` entry or more than one legacy entry, restore a clean pre-upgrade backup before proceeding. Set the legacy entry's `domain` to `declan_local` and, if its `unique_id` is exactly `jarvis_local`, set it to `declan_local`. Keep its entry ID, version, data and options.
3. In `.storage/core.entity_registry`, update `platform` from `jarvis_local` to `declan_local` for each record in `data.entities` with the recorded `config_entry_id`. Apply the same change in `data.deleted_entities` if that list exists. Keep each `entity_id` and `unique_id` exactly as stored. Validate both files as JSON before starting Core. Keep integration storage files and cache directories at their existing paths.
4. Move the legacy folder out of `custom_components` and install the staged `declan_local` folder there. Rename any top-level `jarvis_local:` YAML configuration key to `declan_local:`. Change service actions such as `jarvis_local.play_music_category` to `declan_local.play_music_category` in automations, scripts and dashboards. Update custom WebSocket callers from `jarvis_local/` to `declan_local/`. Preserve existing entity references during this **domain** migration, then verify their actual current IDs in the registry. Do not assume `conversation.jarvis_local_test` exists in an already-migrated installation.
5. Start Core and confirm the entry loads, the existing conversation, STT and TTS entity IDs still resolve, Assist uses the expected providers, and the sidebar and any service automations work. Reload any browser tab with the sidebar already open.

If verification fails, stop Core and restore the pre-upgrade backup and old integration package together. The separate voice bridge retains its own domain.
